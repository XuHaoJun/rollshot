# Benchmark comparison: 2dc1ecd → 0c54975

This branch adds an always-on Gaussian image pyramid as a **round-2 recovery
matcher** in `estimate_motion`. The first commit (`08fb5e3`) fixes a
score-domain bug where the candidate's `second_best_score` was being read
from the coarsest pyramid level while `score` came from level 0 — making
`passes_second_best_margin` see an inflated cross-scale gap that allowed
aliased candidates through on periodic content. The second commit
(`0c54975`) defers pyramid until after coarse + template (coarse-seeded) +
edge has already been verified, so the ~1 ms pyramid cost is only paid
when the cheaper round-1 matchers can't find an offset.

### Notes on the regressions

Every regression above shows up in a stage where the diff does **not**
change any code:

- `pyramid_us` is **0** across all 14 scenarios at p50 — round-2 deferral
  means the median frame never enters pyramid.
- Algorithmic counters (`coarse_candidates`, `ncc_offsets_scored`,
  `ncc_pixel_visits`, `verifier_candidates`) are **identical** between
  before and after for 13/14 scenarios; bad_frame's NCC counters
  decrease (round-1 ranker drops some candidates earlier).
- The diff only touches `crates/rollshot-core/src/matcher.rs` and reorders
  `estimate_motion`'s candidate flow; it does not modify `to_grayscale`,
  `coarse_mad`, `fast_ncc_score_shifted`, `PixelOverlapVerifier`, or any
  of the per-stage hot loops.

The systematic +20-50% wall-time bumps therefore aren't direct algorithmic
regressions — they're code-layout / icache effects from the new pyramid
helpers sharing a translation unit with the hot path (`level0_second_best_sweep`
is already marked `#[inline(never)]` for this reason; the remaining bump
appears to come from LLVM's overall inlining decisions on `matcher.rs`
changing as the file grew).

This is also consistent with same-code bench variance on this machine:
back-to-back runs of the identical `after.jsonl` binary differ by **20-30%**
on `linear_*`, `image_cards`, and `sticky_header` total p50 (e.g.
`linear_horizontal_left` 832 → 664 µs = -20% between two consecutive
runs). Treat any small-frame Δ below the noise floor as inconclusive.

The `long_*` workhorse fixtures (the ones bench cares about for real
screenshot stitching) are flat or slightly improved (-2.7% to +4.2%).
Output correctness is identical.
